# Code of Conduct

DotaStreamKit is a project for Dota 2 streamers, moderators, and developers who want practical stream tools without drama around the work.

## Expected Behavior

- Be respectful and direct.
- Keep issues and pull requests focused on the project.
- Give enough context for other people to reproduce bugs or understand a proposal.
- Assume people may be using different operating systems, Dota settings, OBS setups, and Twitch account flows.
- Keep private data private. Do not post Twitch tokens, client secrets, local config files, or personal information.

## Unacceptable Behavior

- Harassment, threats, hate speech, or personal attacks.
- Posting another person's private information.
- Spam, trolling, or repeatedly derailing technical discussions.
- Publishing exploit details for a security issue before it has been handled through the security policy.
- Using project spaces to promote unrelated services, bots, or repositories.

## Enforcement

Maintainers may edit or remove comments, close issues, lock discussions, or block users when behavior makes the project harder to maintain.

For security issues, use the private reporting process in `SECURITY.md`.

## Русская версия

DotaStreamKit - проект для Dota 2 стримеров, модераторов и разработчиков, которым нужны практичные инструменты для стрима.

Ожидаемое поведение:

- общайся уважительно и по делу;
- держи issues и pull requests в рамках проекта;
- добавляй достаточно контекста, чтобы баг можно было воспроизвести;
- учитывай, что у людей могут быть разные настройки Dota, OBS, Twitch и операционной системы;
- не публикуй Twitch tokens, client secrets, локальные config-файлы и другие приватные данные.

Недопустимое поведение:

- угрозы, травля, hate speech или личные атаки;
- публикация чужих приватных данных;
- спам, троллинг и намеренный увод технических обсуждений в сторону;
- публичная публикация деталей security issue до обработки через `SECURITY.md`;
- продвижение не связанных с проектом сервисов, ботов или репозиториев.

Мейнтейнеры могут редактировать или удалять комментарии, закрывать issues, блокировать обсуждения или ограничивать пользователей, если это нужно для нормальной работы проекта.
